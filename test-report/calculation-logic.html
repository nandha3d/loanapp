Known divergences

  • Two penalty formulas write the same rowsmoney

    The cron accrues Σ max(0, daysOverdue − grace) × default_penalty_per_day, capped by penalty_max_cap. ensurePendingPenaltiesForMissedLoans — which runs on every dashboard load, the penalties page and GET /api/penalties — accrues count(missed instalments) × Loan.penaltyRate, with no grace and no cap. Both write Penalty.grossPenalty, and reconciliation takes the larger. So opening the penalties page can raise a borrower's penalty above the tenant's configured cap, and can charge inside the grace window. MONEY-14 documents only the cron formula.

  • The pure allocator does not skip waived rowstrap

    allocatePaymentsAcrossInstalments keeps a waived instalment in the fill order, so it absorbs payment that then never lands on a payable row. The persistence path filters waived rows out first. No production caller today — a trap, not a live defect. Pinned by CALC-ALO-007.

  • hardBlock is opt-in, not a property of the accountmoney

    Every call site that moves cash out must pass it. Defect ML-122 (the v1 wallet release route) is what happens when one does not — a branch pool driven to −₹10,00,000. Pinned by CALC-FLT-005.

  • The credit-score doc comment is staledoc

    lib/creditScore.ts:2 still says “from 0 to 100”. It returns 300–850. Pinned by CALC-CRS-005.

  • Loan.deduction stores the amount, not the ratedoc

    The column name reads like a rate; it holds rupees. Any report dividing by it is wrong.

  • One schedule branch reads local date partsenv

    The monthly, no-dueDay branch reads local date parts from a Date built at UTC midnight. Verified identical under IST and UTC; unverified west of UTC. Run under TZ=UTC when comparing across machines.

Loan pricing 37 cases

Five interest models. rate means something different in each — that is the largest source of confusion in this module.

upfront_fixed        deduction = rate (₹)          disbursed = P − rate        payable = P
upfront_percentage   deduction = round(P × rate/100) disbursed = P − deduction   payable = P
emi_flat             interest  = P × rate/100        disbursed = P               payable = P + interest
emi_floating         i = (rate/100)/periodsPerYear   EMI = P·i(1+i)^n / ((1+i)^n − 1)
                     payable   = round(EMI) × n      periodsPerYear: 365 / 52 / 26 / 12
interest_only        monthly   = round(P × rate/100) disbursed = P               payable = P + monthly × n
                     APR = rate × 12                 principal is a bullet, OUTSIDE the schedule

split                base = floor(payable / n); the remainder lands on the LAST row
