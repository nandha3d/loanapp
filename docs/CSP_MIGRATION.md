# Content Security Policy (CSP) Migration Plan

## Current State
The application currently implements a baseline Content Security Policy in `next.config.ts`:

```csp
default-src 'self';
script-src 'self' 'unsafe-inline' 'unsafe-eval';
style-src 'self' 'unsafe-inline';
img-src 'self' data: blob:;
font-src 'self';
connect-src 'self';
frame-ancestors 'none';
```

## Vulnerabilities & Risks
1. **`'unsafe-inline'` in `script-src` and `style-src`**: Allows execution of inline scripts and application of inline styles, significantly increasing the risk of Cross-Site Scripting (XSS) attacks.
2. **`'unsafe-eval'` in `script-src`**: Allows the use of `eval()` and similar methods for executing code from strings, which can be exploited if user input is inadvertently passed to these functions.

*Note: Next.js development environment requires `'unsafe-eval'`, but it should be disabled in production.*

## Hardening Plan (Phase 3.5)

### Step 1: Implement Nonces for Scripts
To remove `'unsafe-inline'` from `script-src`, Next.js 13+ supports generating a unique nonce per request using Middleware.

1. Update `middleware.ts` to generate a nonce:
```typescript
import { NextRequest, NextResponse } from 'next/server'

export function middleware(request: NextRequest) {
  const nonce = Buffer.from(crypto.randomUUID()).toString('base64')
  const cspHeader = `
    default-src 'self';
    script-src 'self' 'nonce-${nonce}' 'strict-dynamic';
    style-src 'self' 'unsafe-inline';
    img-src 'self' blob: data:;
    font-src 'self';
    object-src 'none';
    base-uri 'self';
    form-action 'self';
    frame-ancestors 'none';
    block-all-mixed-content;
    upgrade-insecure-requests;
  `
  
  const requestHeaders = new Headers(request.headers)
  requestHeaders.set('x-nonce', nonce)
  requestHeaders.set('Content-Security-Policy', cspHeader.replace(/\s{2,}/g, ' ').trim())

  const response = NextResponse.next({
    request: {
      headers: requestHeaders,
    },
  })
  response.headers.set('Content-Security-Policy', cspHeader.replace(/\s{2,}/g, ' ').trim())
  
  return response
}
```

2. Read the nonce in `app/layout.tsx` and pass it to scripts.

### Step 2: Remove `'unsafe-eval'` in Production
Ensure that no third-party libraries require `'unsafe-eval'` in production. Once verified, the CSP generated by middleware will naturally omit `'unsafe-eval'`, enforcing a strict policy.

### Step 3: Strict `style-src`
Moving away from `'unsafe-inline'` in styles is notoriously difficult in React/Next.js due to dynamic inline styling (e.g., `style={{ ... }}`). It is recommended to rely on CSS modules or utility classes (like Tailwind) and progressively refactor inline styles before strictly enforcing `style-src 'self'`.

## Conclusion
The current baseline CSP provides defense-in-depth against framing (Clickjacking) via `frame-ancestors 'none'` and restricts origins, but requires the above migration to fully protect against XSS vectors.
